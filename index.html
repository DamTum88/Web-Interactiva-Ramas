Entendé las ramas de GitHub sin enredarte!

Una rama es una línea de trabajo independiente. Podés desarrollar una función, probar cambios y recién después unirlos a main mediante un merge.

Empezar Ver flujo completo
terminal 
# Crear una rama nueva
git switch -c feature/login

# Trabajar y guardar cambios
git add .
git commit -m "Agrega login"

# Subirla a GitHub
git push -u origin feature/login

# Volver a main y unirla
git switch main
git merge feature/login

1. Concepto

¿Qué es una rama?

🌳

main

Es la rama principal. Normalmente contiene la versión estable del proyecto.

🌿

feature/login

Una rama separada donde podés trabajar sin romper lo que ya funciona.

🔀

merge

Es la operación que une los cambios de una rama con otra.

2. Crear una rama

Dos formas correctas

Recomendada

Crear y cambiarte a la rama

git switch -c feature/login

Crea la rama y te mueve a ella inmediatamente.

Forma clásica

Con checkout

git checkout -b feature/login

Sigue siendo muy usada y produce prácticamente el mismo resultado.

Importante: una rama local todavía no existe en GitHub. Para publicarla usá git push -u origin feature/login.

3. Flujo de trabajo

De main a merge, paso a paso

1

Actualizar main

git switch main git pull origin main

Empezá desde una versión actualizada para evitar conflictos innecesarios.

2

Crear tu rama

git switch -c feature/login

Usá nombres descriptivos: feature/, fix/, hotfix/.

3

Modificar y hacer commits

git add . git commit -m "Agrega pantalla de login"

Los commits son puntos guardados dentro del historial de tu rama.

4

Subir la rama a GitHub

git push -u origin feature/login

Ahora GitHub ya conoce tu rama y podés abrir un Pull Request.

5

Hacer Pull Request

En GitHub seleccionás Compare & pull request, revisás los cambios y pedís que feature/login se incorpore a main.

6

Hacer merge

git switch main git merge feature/login

También puede hacerse desde el botón Merge pull request de GitHub.

4. Merge

¿Qué ocurre cuando unís ramas?

Antes

main:          A — B
                    \
feature/login:      C — D

Después

main: A — B ———— M
           \      /
feature:    C — D

¿Y si hay un conflicto?

Sucede cuando dos ramas modifican de forma incompatible la misma parte de un archivo. Git no decide por vos: marca el conflicto y te pide elegir qué contenido conservar. 

<<<<<<< HEAD
código de main
=======
código de feature/login
>>>>>>> feature/login

Corregís el archivo, eliminás esas marcas y luego ejecutás git add . y git commit.
